## 1. 背景与目标

样机已装配完成并通过**开环 30V 空载测试**（波形正常）。下一步是闭环调压，但现有设备
只有一台 **300W/60V 直流电源**。本报告回答三件事：

1. 如何用 60V 电源尽量贴近原目标（±200V / 1kW）测试；
2. 闭环程序怎么写、采样时序问题怎么修；
3. 软启动是否仍然必要、上电顺序怎么安排。

**核心结论（先看这个）：**

| 问题 | 结论 |
|---|---|
| 60V 能到 ±200V 吗？ | **不能。** 每路变比 28:14=2:1，60V÷2=30V/路理论上限 |
| 60V 实际能到多少 | **每路 ~24-27V（M≈0.8）**。现腔 Z0=181.5Ω 按额定 Q=1.4 设计，60V 可用电阻换算 Q=2~8 太高，高 Q 无升压区 + 死区/二极管 ~20% 损耗卡住峰值 M（见顶部更正） |
| 60V 下能做什么 | 低压**全功能**验证：开环极性、软启动、闭环稳压（vref 设 24-25V）、负载阶跃、过流保护 |
| 最大功率（现腔） | 60V/46Ω 跨全 ≈ **50W**（105kHz、M≈0.8）。要跑真实功率需**换 60V 专用腔 方案A**（见 `docs/工程开发文档.md` §3） |
| 额定 ±200V/1kW 需要 | 母线 360–440V 直流源（见 §7） |
| 采样时序 | 原 640 周期(60µs) 太慢且异步采样会跟 PFM 打架，已改 12.5 周期 + 周期边界相位锁定 |
| 软启动 | **仍然必要**，与辅助绕组无关（见 §5） |

## 2. 物理约束分析：为什么 60V 到不了 ±200V

变压器：原边 **28T**，副边全绕组 **28T**，中心抽头分两个 14T 半绕组 → **每路变换比
28:14 = 2:1**（注意是全绕组 1:1 的错觉，实际每路 2:1）。

```
Vrail = (Vin / 2) × M(fn, Q)        M ∈ [0.9, 1.05]（95–130kHz 频带内）
60V 输入 → 每路 ≈ 30 × M ≈ ±28~30V     （额定 400V 时 ±200~210V）
```

这是**匝比决定的物理极限**，换更大电流的电源也改变不了。所以测试必须拆成两段：
低压段（现在就做）+ 额定段（补设备后做）。

### 3.3 低压高 Q 的注意点（修正）

现腔 60V 下可用负载（28-46Ω 跨全 / 7-15Ω 每路）换算 Q=2~8（额定满载 Q=1.4），
**高 Q 下增益曲线无升压区、峰值封顶 M=1.0**（FHA 理论实算确认），实际再被
~20% 固定损耗砍到 M≈0.8：

- 增益曲线窄而陡（46Ω 跨全：95k→0.73 / 105k→1.0 / 130k→0.42），一离谐振点就塌；
- 软启动相对平缓：130kHz 时重载输出很低，斜坡到 107kHz 才到目标；
- 重载输出极点 fp_out 上移，20Hz 补偿零点不再精确抵消。若振荡，**优先降低
  `LC_K_GAIN_SCALE`** 或减小负载，而非动模型；
- 谐振电流应力大，别长时间满载；发热集中于死区占空丢失（驱动板 250ns 硬件死区
  + HRTIM 59ns，105kHz 下 ~7-13% 占空丢失）。

## 4. 上电时序

**结论：先开控制板 → 确认就绪 → 合母线 → 软启动，是最优顺序；反过来也安全**
（复位/未初始化期间 PB14/15 为输入悬空，UCC21520 输入内部下拉 → 桥臂全关，不会直通）。

固件当前实现：

```
控制板上电
  → HRTIM 配置好，输出以 130kHz（最低增益）起步，无母线→无功率
  → OLED 显示 fs=130kHz，等 2 秒（LLC_START_DELAY_MS）
  → 此窗口内合 60V 母线（130kHz 低压预充，浪涌最小）
  → 自动软启动：130kHz → 107kHz（~107ms）→ 闭合环路 → 稳压 30V
```

调试器（Keil Watch）里把 `g_llc_start_req` 置 1 可**跳过延时立即启动**。

## 5. 采样时序问题分析（"太慢影响 PFM"）

### 5.1 原问题

原 `adc.c` 用 `ADC_SAMPLETIME_640CYCLES_5`：

- 单次转换 = 640 / 10.6MHz ≈ **60µs**，两通道一次完整读 ≈ **120µs**；
- 控制周期 = 1/107kHz ≈ **9.35µs** → 一次采样比一个开关周期还长，**无法每周期闭环**；
- 640 周期本来是用来平均 LLC 开关纹波的（60µs≈6.4 个周期），对**显示**合理，对**控制**致命。

### 5.2 为什么会影响 PFM

1. **异步采样 + 变频 = 平均窗口对不上**：640 周期窗口覆盖非整数个开关周期；fs 一变，
   窗口覆盖周期数就变，测出的"平均值"里残留的纹波分量随 fs 波动。喂给控制环就成了
   **fs 相关的测量误差**，控制会跟变频（PFM）打架。
2. 即使想每周期采一次，60µs > 9.35µs，中断必然重叠、丢 REP，控制节拍直接乱。

### 5.3 修复（已落地）

| 措施 | 值 | 效果 |
|---|---|---|
| 采样时间 | 640 → **12.5 周期**（~2.4µs/次，两通道 ~4.7µs） | 每开关周期内能完成闭环 |
| 采样时刻 | **REP 周期中断内、开关周期边界软件触发** | **相位锁定**，每次采样同一相位点，无拍频 |
| 频率写入 | 预装载 PER + CMP1(=PER/2)，REP 更新事件生效 | 一次切换到位，无中间频率，自带 1 拍延迟 |

> 不依赖 HRTIM 硬件 ADC 触发（本工程 HAL 版本较旧，缺 `ADC_EXTERNALTRIGINJEC_HRTIM_TRG2`），
> 在中断里软件触发等效实现相位锁定，且对 HAL 版本无要求。

> **2026-08-10 测量精确化（已落地，见 `voltage-sampling/README.md` 与 `docs/调试日志/`）**：
> 电压采样已从"每 REP 双通道连续转"改为 **单通道交替采样**（PA0→PA1→VREFINT 每 3 REP 一轮，
> 每周期只触发 1 通道、读 DR + 清 OVR + 切通道），消除了扫描模式 OVR 挂起抑制 EOC 导致
> 电压恒 0 的问题；读数用 **VREFINT 归一化**（`g_vref=3.0×VREFINT_CAL/VREFINT_counts`）跟踪
> VDDA 漂移/抖动；零点用 **0V 慢速校零**（`|vmeas|<0.5V` 时慢速拉向当前真实共模，τ≈0.5s）。
> 本表"相位锁定"结论不受影响（采样仍在 REP 中断内开关周期边界完成）。

## 6. 闭环程序结构与文件改动

### 6.1 控制架构

```
HRTIM TimerD REP 周期中断（每 9.35µs）
  └─ HRTIM1_TIMD_IRQHandler
       └─ HAL_HRTIM_IRQHandler(TimerD)
            └─ HAL_HRTIM_RepetitionEventCallback  ← llc_ctrl.c 重写
                 └─ llc_ctrl_period_isr()
                      ├─ ADC1 采样两路电压（周期边界，相位锁定）
                      ├─ 状态机：OPENLOOP → SOFTSTART → CLOSED（/FAULT）
                      ├─ 闭环时 2p2z：e=vref−vmeas → w=b0·e+x1 → fs=clamp(fr+w)
                      └─ 写 PERxR + CMP1xR（预装载，REP 生效）
```

### 6.2 文件改动清单

| 文件 | 改动 |
|---|---|
| **新增 `Core/Src/llc_ctrl.c`** | 2p2z 控制、软启动状态机、过流锁存、ADC 快读、REP 回调 |
| **新增 `Core/Inc/llc_ctrl.h`** | 系数/参数宏、状态枚举、API |
| `Core/Src/hrtim.c` | 开 `HRTIM_TIM_IT_REP` 中断；预装载使能；REP 更新使能；MspInit 加 NVIC(TIMD, 优先级0) |
| `Core/Src/stm32g4xx_it.c` | 新增 `HRTIM1_TIMD_IRQHandler` |
| `Core/Src/adc.c` | 4 通道采样 640→12.5 周期 |
| `Core/Src/main.c` | 接入 llc_ctrl；主循环移除 ADC1 电压轮询（中断独占）；加自动软启动/频率扫描/过流判定/OLED 状态显示 |
| `MDK-ARM/voltage_sampling.uvprojx` | 加入 llc_ctrl.c |

### 6.3 修复的旧代码 bug（`voltage-sampling/src/llc_controller.c` 历史副本，已删除）

| Bug | 位置 | 后果 | 修复 |
|---|---|---|---|
| `sTimerxRegs[HRTIM_TIMERID_TIMER_D]` | llc_apply_frequency | TIMERID 是 MCR 掩码位(0x10)，当数组下标**越界** | 用 `HRTIM_TIMERINDEX_TIMER_D`(=3) |
| `HRTIM_CR2_SWU` | 同上 | **宏不存在**，无法编译 | 预装载+REP 更新代替 SWU |
| 只写 PERxR 不写 CMP1xR | 同上 | 变频后**占空比漂离 50%** | 补 `CMP1xR=(per+1)/2` |

> 新 `llc_ctrl.c` 已按修复版实现。仓库 `voltage-sampling/src/` 已同步为修复版，
> 旧的 `llc_controller.{c,h}` 已移除，替换为 `llc_ctrl.{c,h}`。

### 6.4 软启动：仍然必要

辅助绕组引导是软启动的三个理由之一，且已因独立供电而消失；但另外两个**仍然成立**：

1. **启动浪涌**：Co=100µF 全放电时若满载增益直接闭合，充电电流很大；
2. **闭环切入过冲**：积分器从 0 起步，直接闭环比斜坡切入更容易过冲/振荡。

## 8. 逐步测试步骤

> 准备：60V 电源、每路对应负载电阻、示波器（Vds 对地测桥臂中点、Vout 纹波）、
> 电流钳。**首次烧录前把 `LLC_TEST_MODE_OPENLOOP_SWEEP` 置 1**。

### 步骤 0：空载再确认（继承开环结果）
- 烧录后不接负载，先合母线：OLED 应显示 V+≈V-≈0~28V（130kHz 预充），fs=130kHz。

### 步骤 1：开环极性扫描（安全门，必须先过）
- 宏 = 1 烧录。合母线 + 30Ω 负载。OLED 每 800ms 步进 130k→95kHz。
- **判据：V+ 随 fs 下降而上升（fs↑⇒Vout↓）**，即 K_f<0，采样极性正确。
- 若方向相反：采样为同相（`voltage_sample.c` 反相公式与板子不符），**先修极性再闭环**。
- 通过后：把宏置 0，重编译烧录。

### 步骤 2：软启动 + 闭环稳压（30Ω 负载）
- 合母线（2 秒窗口内）→ 自动软启动 → 闭环。
- 判据：输出平滑升至 30V 无过冲；OLED 显示 fs=xxxkHz（应在 107kHz 附近）。
- 异常→查 OLED：`FAULT OC`（过流）、fs 撞 95k/130k 上限（增益不够/振荡）。

### 步骤 3：负载阶跃（120W → 验证动态）
- 15Ω 负载，手动切 30Ω↔15Ω 或加电子负载，观察 Vout 回落与 fs 跟随。
- 判据：电压偏差小、ms 级恢复、不振荡。

### 步骤 4：过流保护（可选，验证 FAULT）
- 短接一路输出（或降低阈值到低于当前电流），确认触发 `FAULT OC` 并停功率级。

### 步骤 5（进阶）：最大功率 250W
- 7Ω 负载 + `LC_OC_THRESH_A=5.0A` 重编译。短时运行观察发热与稳压，勿长时间满载。

## 9. 风险与注意事项

1. **极性未验证前严禁闭环**——采样反相会让环路变正反馈直接打爆；
2. 7Ω 档谐振腔应力大，短时运行，注意温度；
3. 重载振荡优先降 `LC_K_GAIN_SCALE`；
4. 60V 电源只有 5A，电流上限是天然的额外保护层，别绕过它；
5. 额定 400V 测试前，把增益/阈值/vref 全部切回额定值（§3.4 表）。
